## 1. 目标与范围

让 super skill **可单独测、可整体回归、可基准验证**。分三层：

1. **子技能单测**（fast，秒级）：`skills/<name>/tests/`，只测本技能内部，改一处只跑一处。
2. **父级集成测**（medium，分钟级）：`tests/`，只测跨子技能流程（mechanical→viewer→urdf→manufacturing）。
3. **benchmarks**（slow，几分钟到十几分钟）：`skills/mechanical/benchmarks/` 10 题 golden set，每次改 Playbook/scripts 跑一次回归。

这是「深度型 skill 的护城河」—— 现状 `~/.agents/skills/build123d-cad/benchmarks/` 完全不存在，改了 SKILL 没有客观回归基线。

> **分级取舍**：PR 必跑 = 子技能单测 + 父级集成测的 smoke 子集（约 1–2 分钟）。
> 全量 benchmarks 走 nightly + 主分支合并门禁。详见第 8 节「待讨论」。

#### 4.2.1 顶层 + 单题 schema

```jsonc
{
  "_meta": {
    "schema_version": 1,
    "generator": "skills/mechanical/benchmarks/run_all.py",
    "build123d_version": "0.6.x",
    "ocp_version": "7.7.x",

  },
  "<case_id>": {

    "solid_count": 1,                        // 严格相等
    "is_manifold": true,                     // 严格相等
    "volume_mm3": 47497.79,
    "volume_tolerance_pct": 0.5,             // 题级 override (扫掠/装配题更宽)
    "bbox_mm": [60.0, 40.0, 20.0],
    "bbox_tolerance_mm": 0.05,
    "center_of_mass_mm": [30.0, 20.0, 10.0],
    "com_tolerance_mm": 0.1,
    "area_mm2": 7456.0,
    "area_tolerance_pct": 1.0,
    "checksum_sha256": "<step sha256,仅记录>",
    "extra_assertions": [                    // 题级特殊约束(孔位/同轴度/内 void 等)
      {"kind": "hole_centers_xy_mm",
       "value": [[5,5],[55,5],[5,35],[55,35]],
       "tol_mm": 0.05}
    ]
  }
}
```

#### 4.2.2 容差(compare_golden 默认,题级 `*_tolerance_*` 可 override)

| 字段 | 默认容差 | 备注 |
|---|---|---|
| `volume_mm3` | ±0.5 % | 浮点累积;扫掠/装配题在 `volume_tolerance_pct` 放宽到 1~2 % |
| `bbox_mm` 各分量 | ±0.05 mm | 装配题 #10 / 螺旋题 #9 在 `bbox_tolerance_mm` 放宽到 0.1~2 |
| `center_of_mass_mm` | ±0.1 mm | |
| `area_mm2` | ±1 % | 圆角/倒角对面积敏感 |
| `solid_count` / `is_manifold` / `step_reimport_ok` | 严格相等 | **拓扑回归红线**,任何子技能改动不得放宽 |
| `extra_assertions[].tol_mm` / `tol_pct` | 题级声明 | 孔位 / 同轴度 / 内 void / 切口尺寸等 |
| `build_seconds` / `checksum_sha256` | 仅记录、不断言 | 性能趋势看 `report.md`;OCCT 序列化非确定哈希不稳 |

`~/.claude/skills/agent-eval/` 是 ECC 自带的「YAML 任务 + git worktree 隔离 + pytest 判分」工具。
我们把 benchmark 10 题包装成 **两套 agent-eval 任务**(PR 触发跑 fast / nightly + merge-to-main 跑 full),通过公司 CI evals gate 调度(决议见 [01 §8 #11](01-分工与排期.md#8-跨文档待讨论汇总项目经理建议结论))。

### 7.1 触发点与基线对照

| eval 任务 | 触发 | 套件 | 总耗时上限 | 失败处理 | 基线 |

### 7.2 模板字段一览

  provider: company_evals_gate     # 决议见 01 §8 #11
